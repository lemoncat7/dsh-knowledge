# 宿主兼容策略

插件不按 DSH 版本号限制安装或加载，也不维护逐个宿主版本的允许列表。

- 包清单不设置 `engines.dsh`；DSH 宿主模块的 `peerDependencies` 使用 `*`，保留依赖名称，由当前宿主提供。仅删除 `engines.dsh` 不够，因为宿主还会回退检查这些 peer 范围。
- 保留 Node.js 要求、第三方依赖约束和可复现构建所需的开发依赖锁定。开发依赖版本与锁文件中的已解析版本是构建记录，不是宿主加载限制。
- README 与新发布说明不再逐版声明“支持哪些 DSH 版本”。已执行的兼容性测试记录保留在文档中，注明环境、结果和限制，不将测试过的版本变成允许列表。
- DSH 更新后先验证实际接口与功能。只有发现实际问题或需要新功能时才修改、发布插件，不为了补一个宿主版本号单独发版。
- 不限制版本不等于保证所有未来或旧版接口兼容。实际缺少服务或接口时仍保留原有错误提示与权限校验；有真实不兼容时修复接口适配并记录原因，不靠扩大版本白名单处理。

历史验证：[测试记录](compatibility-0.2.2-rc.2.md)。历史文档及旧 Release 描述只反映当时状态。
