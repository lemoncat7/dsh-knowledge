# 检索分阶段优化

参考 WeKnora `256a3f2966866337f7dc3c5fcc10037f2ae18d52` 的分块、上下文补充、诊断设计；本阶段为本项目独立实现，未引入上游运行依赖。

## 第一阶段：命中证据与可解释性基础

- 挂载范围内返回排名靠前的文档后，再按 Markdown 标题、段落、代码围栏选择与查询相关的片段；不再固定截取正文开头。
- 输出章节路径、行号、Unicode 字符偏移、文档版本和截断状态。过长段落/代码块使用有界窗口，明确其只是局部片段。
- `knowledge_read` 新增可选 `expectedVersion`；按搜索位置读取时如果版本已变化，要求重新搜索，避免旧偏移指向新内容。旧调用仍兼容。
- 原始/带书名号或引号的精确文档名称先进入候选集，仍受同一套挂载、项目、知识库、标签和文档状态约束；不扩大搜索权限。
- 摩擦排行返回当前知识库/标题筛选范围内有有效踩坑的文档总数，不受列表分页和召回统计日期限制。提供现有摩擦排序的快捷入口。
- 召回排行默认使用综合得分：召回次数、读取次数、覆盖会话数、摩擦系数、人工优先级共同计算；先在完整权限范围排序再分页，并可查看得分构成，仍可切换单项排序。
- 面向用户的回答采用句段后的可点击行内引用：`（来源：[文档名 · 第 x–y 行](引用链接)）`，不额外堆叠来源列表。点击核验连接、挂载权限和版本后展示原文及高亮行；文档已变更时明确提示，不错误套用旧行号。
- 连续父子标题与正文一起参与片段选择，避免只命中标题；已有相关自动召回时引导模型直接读取，减少重复发现知识库。
- 无新模型请求、数据库迁移或常驻后台进程。片段只在本次检索结果中计算，不建立第二份正文。

验证：中文后半段匹配、Unicode 偏移、长代码块、连续标题、精确标题候选拥挤、权限撤销、版本变化、摩擦分页汇总、远程读写权限、旧服务兼容、真实 DSH Markdown 引用点击和浏览器响应式测试。

边界：行内引用依赖模型在回答中使用工具提供的链接，历史回答不会补写。泛化词造成的主题误召回仍需评测后改进；本阶段不声称已解决所有相关性问题。

## 第二阶段：持久化分块索引和评测

已实现并部署（2.16.0）：

2026-10-28 正式环境验证：221 篇文档索引就绪，待处理与失败均为 0；原文、状态与版本保持不变。395 项自动化测试及浏览器交互验证通过。此结果不代表页面启动延迟已解决，服务端偶发停顿和宿主页面渲染开销需另行排查。

- 在原 SQLite 中保存可丢弃的结构索引：段落范围、Unicode 偏移、行号、标题路径与父子章节；不复制第二份正文，不引入向量模型。
- 文档写入、版本更新、归档在同一事务中标记索引失效；删除级联清除派生记录。索引只有版本匹配且状态正常时才使用。候选仍由原有全文检索和同一套权限筛选产生，不改变排名算法。
- 后台每批最多处理 4 篇、批间让出事件循环，12ms 软预算（单篇处理不可抢占）。启动只登记缺失 ID，不同步解析全库；重启继续处理未完成工作。
- 只改标题等元数据时可以复用相同正文哈希的结构。索引失败自动退避重试（5 秒起，最长 1 小时），仍可即时用按需解析检索已保存的正文；损坏索引丢弃重建。
- 相关段落不足 420 码点时补充同一章节内完整的相邻段落，保持单段连续原文，不跨章节拼贴，不重复计入重叠内容；长段落和代码仍采用有界窗口。
- 知识目录搜索框下方显示索引进度，点击打开统一居中弹窗，分页查看待处理和失败文档，支持单篇/当前范围全部失败项重试。显示的是实际知识库服务的状态，非客户端独立进度；当前目录、会话挂载、项目与标签策略同时生效。
- `GET <api-prefix>/retrieval-index` 需要读取权限，默认只返回计数；`details=1&state=pending|failed&offset=0` 分页返回最多 30 篇文档的标题、版本及重试元数据，不返回正文、凭据或原始错误内容。`POST <api-prefix>/retrieval-index/retry` 需要管理员权限，可传 `documentId` 限定单篇，且不能越过当前范围。
- 状态更新不重绘文档编辑器；处理中每 3 秒、就绪后每 30 秒查询轻量状态，切页/隐藏/不可见时暂停，网络错误退避，旧服务不支持时提示升级而非显示假进度。用户点击详情时才加载任务列表。
- 本地/中央服务均使用同一实现；新版中央搜索会传回片段及索引版本，新客户端连接旧服务时继续按需解析。中央知识库的索引应在中央服务构建，不在每个客户端复制。
- 片段读取显式传 `includePassage: true`（GET 参数 `includePassage=1`）；会话召回自动开启。普通文档搜索、回写查重和抽取等无需片段的调用保持原成本与返回格式。

评测命令：`npm run eval:retrieval`；已有构建时可运行 `node scripts/evaluate-retrieval.mjs /path/to/labeled-dataset.json`。数据结构参考 `test/fixtures/retrieval-evaluation.json`。脚本只读输入数据集并新建临时数据库，不访问生产库，不请求模型/网络，结束删除自己的临时目录，只输出汇总指标。真实评测数据应留在本地，不提交私有正文。

指标包含 hit rate / recall / precision / MRR / nDCG@5、无答案问题的空结果率、证据覆盖率、权限泄露、行号/偏移一致性、预热后的 P95 耗时和片段字符预算，并比较索引与回退路径的候选一致性。

当前随附数据为 **10 篇人工样本文档、12 个代表性回归问题**，不等于线上真实问题评测集。短文档上索引读取也有成本，不能凭这组数据声称全场景加速或召回相关性已提升。新排序/向量模型仍需先补齐本地真实问题的人工相关性标注，再做对照实验。

在引入新排名算法前建立真实问题评测集，分别检查命中率、相关性、权限隔离、P95 耗时和注入上下文大小。第一阶段的按需片段选择不等同于完整分块检索。

## 当前后续：速度与稳定性优先

2.16.1 已实现并部署：索引状态组件非阻塞加载、失败下载可靠重试、可见性请求合并与刷新间隔、读取超时与取消、清单无变化免写盘、索引小批事务提交。407 项自动化测试及慢模块/断网故障注入浏览器验证通过。

正式环境验证：221 篇文档正文/状态/版本不变，索引全部就绪；一次本机直连浏览器测量中，目录首次就绪 1584ms，再次打开 1009ms。此测量不包含宿主页面和公网链路，不代表完整 DSH 页面或所有后续请求的耗时。

优先继续定位宿主内嵌页面渲染和服务端偶发停顿；不以增加模型、缓存私有正文或绕过权限换取表面上的提速。

2.16.2 已部署：将宿主入口的连接读取合并、限时和取消独立为连接客户端；连接保存与旧读取之间增加隔离，避免旧响应覆盖新状态。后台复查临时失败保留现有编辑器，权限撤销则关闭页面。关闭工作区清理重连监听和读取请求，不保留隐藏运行的 iframe。417 项测试与两组浏览器回归通过；正式环境 221 篇文档保持不变，索引全部就绪。详见 `releases/2.16.2.md`；不新增向量模型。

## 暂缓：可选混合检索

按当前产品需求不实施向量模型接入，下面仅作为未来备选，不属于已实现或待上线功能。

关键词 + 向量召回、可选重排；后台增量向量化、候选数与耗时预算、不可用时回退全文检索。不在默认聊天路径额外串行调用大模型；不自动接入 WeKnora 的独立聊天/Agent 系统。

## 摩擦系数边界

摩擦来自具体有效踩坑记录，不是召回次数或失败关键词计数。模型主动工具入口已具备，但不保证每次都会调用；只读挂载不允许反馈。不会为让数字变大而回填猜测的事故，也不会修改真实历史记录。人工覆盖 0、无记录、记录已撤销需要区别于计算故障。
