# 会话主动记录踩坑

`knowledge_record_incident` 注册在所有会话的知识工具中，不属于伙伴专用工具。

- 触发：实际失败、用户明确纠正或已核实的返工/阻塞，与已读取的挂载知识文档直接相关。
- 无需用户另外说“记录踩坑”；知识挂载指令和工具描述均提示主动调用。
- 必填：文档短引用、稳定事件键、具体依据、经验及严重程度（1/3/6）。不按召回次数推断事故，不把等待和每次重试分别记分。
- 同会话、同文档、同事件键跨轮次去重。重试须保持原始内容；同键内容变化返回冲突，不能换键绕过去重。独立复发才使用新事件键。
- 来源会话、事件键、依据及经验写入踩坑原因，现有摩擦记录详情可查看和由管理员撤销；文档正文和版本不变。
- 只读挂载拒绝记录。audit/direct 挂载允许独立召回反馈；这不是正文回写，不新增正文评审。中央 API 需要 read/write 权限，人工系数设置及撤销仍需要管理员权限。
- 未找到关联文档时不强行记录；服务未升级、权限不足、网络错误时不得声称成功。

这是模型主动调用的能力，并非无条件后台采集：不能保证每一轮都自动识别到踩坑，也不能可靠识别不同会话中人为使用不同事件键的重复事件。

召回排行默认按综合得分排序，保留按召回次数等单项排序。综合得分公式与范围见 [2.15.7 说明](releases/2.15.7.md)，点击分数可查看五项贡献；这是展示用的关注价值，不改变查询相关性门槛。某页摩擦全部为 0 并不意味着整个库没有踩坑。汇总展示当前筛选范围内有有效踩坑记录的文档数，并提供「查看踩坑排行」；该数量不限召回统计日期，撤销记录、封存文档和封存知识库不计入。连接旧中央服务时不推测全库统计；若尚不支持综合得分，会提示升级或切换原有单项排序。
