# 工作日历

「工作记录」下有两个独立功能：「工作日历」和「工作日报」。分别通过左侧导航进入各自页面；原有 view=worklog 链接仍打开日报，view=calendar 打开日历。日历用于手工或通过 AI 记录目标、日程、提醒及实际工作；未指定时间时创建全天目标，也可安排跨日时段。月视图浏览日期分布并提供溢出数量，周视图浏览时间安排，列表视图展开完整标题、类型、分组和标签；手机按日期查看当天清单。分组、类型及关键词筛选在当前日期范围内本地完成，不为每次输入重复读取数据库。支持进度、优先级、标签、关联项目、编辑改期、回收站和 iCalendar 文件导出。只有目标参与每日进度和未完成结转。日程、提醒不会结转；提醒时刻独立于事件结束时间。日历不自动执行目标，不调用模型生成计划。

数据与日报分别保存，使用相同的工作记录 SQLite 文件和当前知识库连接。远程连接失败不会静默写到本地。数据不自动加入模型上下文，AI 按需查询。界面仅在可见时每 15 秒检查更新，离开日历后停止。

每条目标旁直接提供「每日进度」入口、记录数和最近一条摘要，也可从目标编辑页打开。独立弹窗可查看、补写、编辑和删除每天的进度，默认补写目标所属日，结转前后的条目共用完整历史。后台补写会在下一次可见更新检查时刷新，编辑中的草稿会保留。编辑进度保留它所属的日期。创建日期显示最初创建目标的日期。开启「安排具体时段」后，开始和结束各用一个日期时间输入框，两者并排。

## AI 与 API

统一 `knowledge` 工具的 `knowledge_calendar` 操作包含 `info/list/read/create/update/delete/restore/changes/export/progress-read/progress-write/reminders/reminder-ack`。先 `info` 获取日历身份与时区，再查指定日期范围。`list` 的 `from` 包含当天，`to` 不包含当天，最大 370 天；支持状态、标签、关键词和分页。

写操作均需唯一 `requestId`；网络结果不确定时必须在原连接以相同编号和相同参数重试。更新、删除和恢复需要当前 `revision`，冲突需重读。可传 `calendarId` 防止在切换后的连接上误写。`create` 传 `event`，`update` 传 `patch`。日期使用 YYYY-MM-DD；全天 `endDay` 为不含当天的结束日期，默认下一天；定时条目必须提供带 UTC 偏移的 `startAt/endAt`，使用 IANA `timeZone`。界面显示全天结束日期为包含当天。

每日进度通过 `progress-read` 传 `id` 和 `day` 读取，通过 `progress-write` 传相同日期、读取到的 `revision`、`text` 和 `requestId` 保存。空白记录的修订号为 0。AI 可以在获得授权后引用日报中的已有进展补记。

明确说“提醒我／到时通知／记个目标／安排日程／加入日历”时，应调用统一 knowledge 工具的 knowledge_calendar 操作实际保存，不只口头答应；闲聊中出现这些词不代表创建授权。先 info 获取时区、日期与 groups.items，再选择 kind: goal/event/reminder/work 和 groupId；提醒需明确时刻，用带偏移 ISO 的 remindAt，不编造时间或宣称未设置时间的条目会通知。

删除仅产生可恢复墓碑，无永久删除接口，不与笔记的覆盖/永久删除确认流程混用。目标完成状态以真实反馈为准，不从聊天中臆测完成。工具不会获得外部日历账号凭据。Bearer API 读取需要 read，写操作需要 write；界面沿用 DSH 认证与来源校验。

HTTP 路径在知识库 API `/worklog/` 下：GET `calendar-info`、`calendar`、`calendar-event`、`calendar-changes`、`calendar-export`、`calendar-progress`、`calendar-progress-history`，POST `calendar-create`、`calendar-update`、`calendar-delete`、`calendar-restore`、`calendar-progress-write`。浏览器认证入口为 `/worklog-control/v1/` 下同名路径。

## 日历设置

「更多 → 日历设置」里的「日报生成后自动更新当天目标」默认关闭。开启后，后续生成成功的日报会按其所属日期排队核对目标，并复用日报的模型设置进行一次补充核对。部分进展写入当日记录，有用户明确确认或手工补记证实完成时才勾选完成。手工进度优先，补跑不会产生重复记录。尚未经手工编辑、也没有人工进度的后续结转副本会随原目标完结，包括跨工作日和多次结转。设置中的「核对最近 7 天的已有日报」可显式补核历史，最多支持 API 指定连续 31 天；排队期间重复点击不会重复入队。没有已有日报的日期不会生成进度。

「日历设置」可选择每周工作日，并为调休、假期添加指定日期的工作／休息例外。默认周一至周五，日期例外优先，至少保留一个每周工作日。设置保存使用修订号避免多端覆盖。目标编辑页的「未完成时结转到」可选「下一天」或「下一个工作日」（API `carryMode: daily | workdays`）。旧目标保持原有按天规则；选择工作日后，结转会跳过休息日，停机跨多天也只补结转一次。修改工作日设置只影响后续结转，不删除已存在的历史目标。

日历列表一次批量聚合目标进度摘要；更新检查使用独立进度游标，空闲时不写数据库，也不为每条目标单独发起进度请求。设置可见时每 15 秒读取一次，隐藏时降为 30 秒。弹窗复用工作区的玻璃材质、滤镜和边缘高光，内容区使用连续表面，支持明暗及减少透明度偏好。

从工具栏的「登录」或「账号」打开日历账号，左侧选择 iCloud 后可配置双向同步。同步默认关闭。先输入 Apple 账户邮箱和应用专用密码，验证后选定可写的日历，再单独开启同步。旧关联自动归入默认「工作」分组。可在「更多 → 管理分组」添加、改名或设置分组颜色，再在「账号 → 读取已登录账号的日历」里增加关联、选择双向／仅上传／仅下载／暂停。无需重复输入已保存密码。只读日历仅允许下载或暂停，每个本地分组和外部日历只能关联一次；未关联分组只保存在 DSH。解除关联和暂停保留两端条目，不等于删除。已绑定条目更换分组前需解除原分组的账号关联，不能把已有同步日历直接重绑到其他分组。中央连接模式由中央实例执行同步，只有中央管理员能改设置。应用密码只用于 iCloud CalDAV 请求，使用本地密钥加密保存，设置和工具不会返回密码。

开启后约每五分钟检查 iCloud，拉取的变更会自动显示在工作日历。也可点击「立即同步」提前检查。首次启用以当前日历日期为起点。同步目标标题、全天日期或开始与结束时刻，以及目标备注。每日进度、完成状态、标签和优先级保留在知识库。已有同步条目两边各有不同备注时，会按冲突处理。重复事件与邀请保留在 iCloud，对同一目标的双端改动可在「待处理」选择版本。双向关联会自动传播正常的单边删除：DSH 移入回收站后按 ETag 删除对应 iCloud 条目；iCloud 删除后，本端未有其他编辑的条目移入可恢复回收站。删除与另一端编辑发生冲突时保留双方版本供处理。恢复会复用原同步 UID，网络结果未知时通过持久操作意图恢复，不重复创建或误删恢复的条目。此前显式选择“仅保留另一端”的记录继续保留。断开连接会停止同步并移除已保存的凭据。

`@lemoncat7/dsh-knowledge/calendar` 仍导出供其他服务使用的适配器类型和增量接口。iCalendar 文件也可继续手工导出。

## 到期提醒

新建/编辑中可为目标、日程、提醒配置「到时间提醒」，保存为明确的 remindAt 时刻。DSH 侧栏的到期提醒按钮显示未处理数量，到期时显示提示并可打开对应日期；「知道了」只保存提醒知晓状态，不完成目标、不删除事件。知晓按条目与提醒时刻持久化；改期会形成新提醒，刷新或重启后旧提醒不会重新出现。

DSH 客户端可见时最多每分钟读取一次提醒，已知下一次提醒更近时按该时刻检查；页面隐藏时暂停，恢复可见后补查。无定时数据库写入或模型调用。收起提示后仍保留未处理角标，同一浏览器不会反复弹出相同提醒。DSH 未运行时没有 DSH 页面提示，重新打开会展示未知晓到期提醒。

关联 iCloud 且允许上传时，提醒以标准 VEVENT/VALARM 同步，由 Apple 日历提供手机/电脑系统通知；这是日历通知，不是 Apple「提醒事项」VTODO 列表。已有外部相对/绝对提醒可读取，清除提醒会同步清除通知。每日进度、标签、完成状态仍仅保存在 DSH。Google 尚未提供登录连接。

新增 HTTP：GET calendar-reminders；POST calendar-reminder-ack（requestId、calendarId、id、原 remindAt 数字时间戳）、calendar-groups-settings（revision、items）、calendar-icloud-calendars（读取已保存账号）、calendar-icloud-mappings（revision、mappings，每项 groupId、calendar、direction）。分组和账号配置需要管理员权限；读取提醒沿用 read，知晓沿用 write。
